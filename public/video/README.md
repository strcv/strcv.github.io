# Watch Later — раздел `/video`

Статический каталог выжимок из видео. Без сборки: одна HTML-страница читает `data/index.json`
и рисует очередь, фильтры и страницы разборов. Работает на GitHub Pages как есть.

## Куда положить

Скопировать папку `video/` в корень репозитория личного сайта. Адрес получится
`https://<логин>.github.io/video/`, при своём домене — `https://домен/video/`.
Ничего в остальном сайте менять не нужно.

Перед запуском:

1. В `index.html` поправить ссылки в шапке (`/asapmail/`, `/vacancy/`, `/blog/`) и в подвале
   (`@watchlater`, `@watchlater_bot`).
2. Из `data/index.json` удалить все демонстрационные записи — оставить `{"items": []}`.

Локально страницу нужно открывать через сервер, иначе `fetch` заблокирует браузер:

```bash
cd video && python3 -m http.server 8000   # → http://localhost:8000
```

## Структура

```
video/
  index.html                  весь интерфейс: очередь, поиск, фильтры по тегам, страницы разборов
  data/index.json             каталог — единственный источник правды
  data/transcripts/<slug>.md  полные расшифровки
```

Страница разбора живёт по адресу `/video/#/<slug>` — этот адрес и уходит в Telegram-пост.

## Схема карточки

| поле | тип | обязательно | что это |
|---|---|---|---|
| `slug` | string | да | латиницей, через дефис; это же имя файла транскрипта и часть URL |
| `video_id` | string \| null | нет | ID ролика на YouTube — из него берутся обложка и ссылки на тайм-коды |
| `thumb` | string \| null | нет | своя обложка; если пусто и есть `video_id`, берётся `i.ytimg.com` |
| `url` | string | да | ссылка на оригинал |
| `title` | string | да | заголовок по-русски — его пишет модель, не копия оригинального |
| `original_title` | string | нет | как называется у автора; участвует в поиске |
| `channel` | string | да | название канала |
| `duration` | number | да | секунды |
| `published` | string | нет | дата ролика, `ГГГГ-ММ-ДД` |
| `added` | string | да | дата попадания в очередь, `ГГГГ-ММ-ДД`; по ней сортировка |
| `lang` | string | нет | язык оригинала |
| `summary` | string | да | одна-две фразы: о чём видео. Это же идёт в Telegram |
| `takeaways` | string[] | да | 3–5 выводов, каждый — законченная мысль, а не заголовок |
| `timecodes` | `{t, label}[]` | нет | `t` в секундах; ссылка открывает YouTube с этой метки |
| `tags` | string[] | да | 1–2 тега из закрытого списка |
| `transcript` | string \| null | нет | путь к `.md` относительно `/video/` |
| `tg_post` | string \| null | нет | ссылка на пост в канале, проставляется после публикации |

Список тегов держать закрытым, иначе через месяц будет тридцать штук по одной записи.
Стартовый набор: `AI`, `агенты`, `разработка`, `продукт`, `стартапы`, `деньги`, `интервью`, `туториал`.

## Конвейер

```
ссылка → Гермес → yt-dlp (метаданные + субтитры) → Claude (скил recap) → JSON
   → подтверждение в Telegram → коммит в репо → GitHub Pages пересобирается
   → n8n по расписанию постит в канал → в карточку дописывается tg_post
```

Ловить деплой вебхуком не нужно: сайт и канал получают данные от одного и того же
оркестратора, а не друг от друга. Сайт — просто витрина файла, который уже лежит в репо.

Коммит делается через GitHub Contents API: `PUT /repos/{owner}/{repo}/contents/video/data/index.json`
с текущим `sha` файла. Писатель один (Гермес), поэтому гонок не будет.

Если хочется гарантии, что страница обновилась до поста в Telegram, — проверять
`GET /repos/{owner}/{repo}/pages/builds/latest` до статуса `built`, обычно 30–60 секунд.
