# Watch Later — раздел `/watch-later`

Каталог выжимок из видео. Страницы собирает Astro из коллекции `videos`: список —
`/watch-later/`, разбор ролика — `/watch-later/<slug>/`. Этот адрес и уходит в
Telegram-пост.

## Где что лежит

```
src/content/videos/<slug>.json            запись — один ролик; имя файла = адрес разбора
src/content.config.ts                     схема коллекции videos и закрытый список тегов
public/watch-later/transcripts/<slug>.md  полные расшифровки, отдаются как есть
src/pages/watch-later/                    страницы списка и разбора
src/components/Video*.astro               разметка: список, разбор, обложка
```

Коллекция может быть пустой: сборка проходит, `/watch-later/` показывает пустое
состояние.
Папку в git держит `src/content/videos/.gitkeep`.

## Схема записи

Файл — один JSON-объект. `slug` внутрь не пишется: это имя файла — латиница в нижнем
регистре, цифры и дефисы.

Схема строгая: неизвестное поле, пустая строка, тег не из списка или дата не в том
формате роняют сборку, и сайт не выложится, пока запись не поправят. В ошибке — имя
файла и поле.

| поле | тип | что это |
|---|---|---|
| `title` | string | заголовок по-русски — его пишет модель, не копия оригинального |
| `summary` | string | одна-две фразы: о чём видео. Это же идёт в Telegram |
| `channel` | string | название канала |
| `duration` | number | секунды |
| `url` | string | ссылка на оригинал, `https://` |
| `videoId` | string \| null | ID ролика на YouTube, 11 символов; у роликов с других площадок — `null` |
| `thumb` | string \| null | своя обложка: `https://…` или путь от корня сайта. Задана — берётся она, иначе кадр с YouTube по `videoId`, иначе заглушка |
| `added` | string | дата попадания в очередь, `ГГГГ-ММ-ДД`; по ней сортировка |
| `published` | string | дата ролика, `ГГГГ-ММ-ДД` |
| `lang` | string | язык оригинала: `en`, `ru` |
| `takeaways` | string[] | 3–5 выводов, каждый — законченная мысль, а не заголовок |
| `timecodes` | `{t, label}[]` | `t` в секундах, не дальше `duration`; ссылка открывает ролик с этой метки |
| `tags` | string[] | 1–2 тега из закрытого списка |
| `transcript` | string \| null | путь `/watch-later/transcripts/<slug>.md` |
| `tgPost` | string \| null | ссылка на пост в канале; проставляется после публикации |

Все поля обязательны, кроме `thumb` и `tgPost`. Где тип допускает `null`, значение
пишется явно.

Список тегов держать закрытым, иначе через месяц будет тридцать штук по одной записи:
`AI`, `агенты`, `разработка`, `продукт`, `стартапы`, `деньги`, `интервью`, `туториал`.
Новый тег появляется только правкой `TAGS` в `src/content.config.ts`.

## Конвейер

```
ссылка → Гермес → yt-dlp (метаданные + субтитры) → Claude (скил recap) → JSON
   → подтверждение в Telegram → коммит в репо → сайт пересобирается
   → n8n по расписанию постит в канал → в запись дописывается tgPost
```

Ловить деплой вебхуком не нужно: сайт и канал получают данные от одного и того же
оркестратора, а не друг от друга. Сайт — просто витрина файлов, которые уже лежат в репо.

Коммит делается через GitHub Contents API, файл на запись:
`PUT /repos/{owner}/{repo}/contents/src/content/videos/{slug}.json`. Новый файл — без
`sha`, правка существующего (дописать `tgPost`) — с его текущим `sha`. Транскрипт кладётся
отдельным файлом в `public/watch-later/transcripts/{slug}.md`. Писатель один (Гермес), поэтому
гонок не будет.

Поля `tg_text` и `skip` из ответа скила в запись не попадают: лишний ключ уронит сборку.

Сайт собирается в GitHub Actions (`.github/workflows/deploy.yml`). Запись, которая не
прошла схему, делает прогон красным — страница не появится, пока файл не поправят.

Если хочется гарантии, что страница обновилась до поста в Telegram, — проверять
`GET /repos/{owner}/{repo}/pages/builds/latest` до статуса `built`, обычно 30–60 секунд.
